### 一、 功能维度展开分类

#### 1. 数据库连接（杨硕）

- **物理存储引擎**：定义存储根目录，实现文件由 `OriginalName` 到 `UUID.mp3` 的映射存储。
- **数据库建模**：构建 `audio_assets` 与 `sys_users` 表，确立雪花算法或 UUID 作为主键。
- **IO 安全策略**：编写路径锚定工具类，杜绝 `../` 路径穿越攻击。

#### 2. 增删改查（阚德扬）

- **增**：实现“本地落盘成功 + 数据库写入成功”的事务控制。
- **删**：实现物理文件与 DB 记录的同步抹除（必须关联权限校验）。
- **改**：实现仅针对 `file_name` 字段的修改。
- **查**：实现基于 `create_time DESC` 的分页查询。

- **音频转发流 (Stream)**：实现通过 ID 读取文件流，不在前端暴露物理路径。
#### 3. 安全与认证 （于子桐）

- **鉴权中间件**：基于 JWT 的角色识别（Role 0 vs Role 1）。
- **序列化处理**：全局处理 Long 转 String，防止前端精度丢失。
- **异常拦截**：统一处理文件占用、空间不足等 IO 异常。

#### 4. 前端展示与交互 (于子桐)

- **上传模块**：带进度条的上传组件，支持文件类型校验。
- **管理控制台**：
    - **Level 0（管理态）**：展示删除/修改按钮。
    - **Level 1（操作态）**：仅展示列表与预览，隐藏敏感操作。
- **音频播放器**：基于 HTML5 Audio 的流播放。

- **职责范围**：核心业务逻辑、数据库、IO 操作。
- **具体任务**：

    3. **核心攻坚**：实现 `Delete` 接口中的“物理+数据库”同步逻辑，确保文件被删除时不会漏掉。
    4. 编写音频资源转发接口，通过流（InputStream）方式返回音频。

#### **于子桐：前端开发 (Frontend Engineer)**

- **职责范围**：UI 界面、用户交互、数据请求封装。

    3. **核心攻坚**：处理角色权限显隐逻辑。判断如果 `role_level != 0`，则在 UI 上禁用或通过逻辑隐藏“物理销毁”按钮。
    4. 处理 ID 精度保护（Long 转 String 的接收）。

#### **于子桐：全栈/架构与 QA (Stability & Quality)**

- **职责范围**：安全防护、测试验证、用户模型（Role）、部署。
- **具体任务**：
    1. **用户模块**：编写登录接口及 JWT Token 生成逻辑，区分 `role_level` 0/1。
    2. **安全性审计**：编写路径过滤逻辑，防止前端通过传参恶意删除服务器非音频目录文件。
    3. **核心攻坚**：MD5 校验逻辑。在上传时生成 `hash_code`，用于防止重复存储。
    4. **QA 验证**：使用 Apifox 编写全流程测试用例（如：模拟物理文件缺失时，删除接口能否正常清理数据库记录）。

### 三、 合理化建议（针对 3 人组）

1. **接口先行**：建议第一天由 **人员 A** 和 **人员 C** 确定好全部的 JSON 字段格式（尤其是 ID 类型），方便 **人员 B** 直接使用 Mock 数据 Mock 开发。
2. **IO 路径统一**：在 `application.yml` 中统一配置 `storage-root-path`，不要在代码里硬编码 `D:/files`，避免换环境（如部署到 Linux）时崩溃。
3. **放弃冗余功能**：MVP 第一版本**切勿**做“音频长度解析”、“波形图展现”、“批量勾选删除”等功能，全员目标应只有两点：**“上传不崩”** 和 **“删除必净”**。
